# plan 0.1.2 — float64 diffusion and player color cap

Replaces 4-bit fixed-point channels with `Float64Array` in native `0..255` units so zero-depletion
diffusion converges to 255 without quantization stalls, and adds per-player color budget rules.

## float64 diffusion and rendering

- `grid.ch` and `grid.back` use `Float64Array(CELLS)` with `MAXV = 255` (no `SHIFT`).
- `spreadPass` combines decay and spread in a symmetric gather loop:
  - `base = max(0, cur[i] - deplete)`
  - outflows `(o0 + o1) + (o2 + o3)` and neighbor inflows `(v0 + v1) + (v2 + v3)` are summed
    in horizontal-then-vertical pairs, so `mirror` stays bit-for-bit identical under `x -> N-1-x`.
- `renderDraw` rounds each channel with `(v + 0.5) | 0` so asymptotic approach to `255` displays
  as `255`.

## player color cap

Two rule sliders control the maximum total color a player may keep on the map:

- `maxColor`: base max color (`CAP_STEPS` from `0` to `1M`, plus `Infinity` / `∞` default = off).
- `territoryCap`: extra color allowed per claimed cell (`0..510`, step `5`, default `0`).

For each channel `c`, after `sourcePass`, `reactPass`, and `countPass`:

- Effective cap is `cap = settings.maxColor + settings.territoryCap * grid.count[c]`.
- When `settings.maxColor < Infinity` and `sum(ch[c]) > cap`, all cells in `ch[c]` scale by
  `cap / sum` (or zero if `cap <= 0`), followed by `countPass` to keep ownership counts current.
- `+ / claimed` slider is disabled in the UI while `maxColor` is `∞`.
